# Invoice Generator — Product Requirements Document (PRD)

> This document describes the product from a **product perspective only**.
> It intentionally contains **no technology stack or database details** — see
> `Tech.md` and `DB.md` for those.

---

## 1. Overview & Vision

**Invoice Generator** is a simple, fast invoicing tool built for **freelancers**.

From a single place, a freelancer can:

- Enter and maintain their own sender details.
- Manage a list of clients.
- Create invoices on a clean, fixed layout.
- Generate a professional PDF for each invoice.
- Generate a payment link so clients can pay online.
- Email the invoice (with PDF attached and a payment link) to the client in one click.
- Track whether an invoice has been paid, and resend it when needed.

The vision is to remove friction from getting paid: a freelancer should be able
to go from "work is done" to "invoice sent and payable" in a couple of minutes,
without spreadsheets, manual PDF exports, or chasing payment details.

---

## 2. Primary Goal

Enable an individual freelancer to **create, store, send, and get paid for
invoices** quickly and reliably, while keeping a clear record of which invoices
are paid and which are still outstanding.

---

## 3. Target User & Role

### Target user
Independent freelancers who bill clients directly (designers, developers,
consultants, writers, etc.). They typically manage their own business, have a
modest list of recurring or one-off clients, and need a lightweight way to
issue invoices and collect payment.

### Single role: "User"
The product has exactly **one role: "User"**. There are no admins, teams,
organizations, or shared accounts.

A User can only ever:

- See and edit **their own** profile / sender details.
- See and manage **their own** clients.
- See, create, edit, and manage **their own** invoices and the PDFs generated
  from them.

A User can **never** see another User's profile, clients, invoices, or PDFs.

## 4. In-Scope Features

### 4.1 Authentication
- **Register** with email and password.
- **Login** with email and password.
- **Logout**.
- **Forgot-password reset** flow (request a reset and set a new password).
- No email confirmation step is required to start using the app after
  registering.

### 4.2 Profile / Sender Details
The User maintains their own sender details, used as the "From" block on every
invoice.

Fields (**all optional**):
- Full Name
- Company Name
- Email
- Address
- VAT ID
- Website

Behavior:
- These details are **auto-pulled into the "From" section** of every new invoice.
- Editing the profile updates future invoices only; previously created invoices
  keep the details they were created with (see **5.4 Snapshots**).

### 4.3 Client Management
The User maintains a list of clients.

Fields (**all optional**):
- Full Name
- Company Name
- Email
- Address
- VAT ID

Behavior:
- Full **CRUD**: create, view/list, edit, and delete clients.
- When creating an invoice, the User **selects a client from a dropdown**, which
  fills the invoice "To" section.
- Deleting a client is allowed at any time. Existing invoices that referenced
  that client **keep their own copy** of the client details (see **5.4
  Snapshots**) and are not affected.

### 4.4 Invoice Creation
Invoices are created on a **fixed layout** (no branding or layout customization).

**Header**
- **From** — auto-filled from the User's profile/sender details.
- **To** — filled from the selected client.
- **Invoice Number** — auto-generated by the system; the User never types it.
- **Invoice Date** — defaults to today.
- **Due Date** — defaults to today + 14 days.
- **Currency** — chosen from a fixed shortlist; exactly one currency per invoice.

**Line items** (one or more), each with:
- Description
- Quantity
- Unit type — **hours** or **flat** (label/display only)
- Price (per unit)
- VAT rate (a free numeric percentage per line, e.g. `17`, `20`, `0`)

**Computed totals** (shown automatically):
- **Subtotal** — sum of line amounts.
- **Tax** — sum of per-line VAT.
- **Total** — Subtotal + Tax.

**Footer**
- Comments (free text).

**Explicitly not part of the invoice:** bank account fields, interest fields, or
a "type" field. (See **6. Out of Scope**.)

### 4.5 PDF Generation
- A **PDF is generated for each invoice**.
- The PDF is **regenerated whenever the invoice is edited** so it always matches
  the current invoice contents.
- Each PDF is stored as a private document **tied to its invoice** and is only
  accessible to its owner.
- The PDF uses a fixed, consistent, readable layout with no logo/branding upload.

### 4.6 Previous Invoices (List)
A paginated list of the User's invoices.

Each row shows:
- Invoice Number
- Client
- Invoice Date
- Due Date
- Total
- Status

Row actions:
- **View** (open invoice details / preview)
- **Edit** (only when allowed — see **5.3**)
- **Delete** (only when allowed — see **5.3**)
- **Resend** (email the invoice to the client again)
- **Download PDF**

### 4.7 Invoice Status
- Status is limited to exactly two values: **"paid"** and **"not paid"**.
- There is **no "draft" status** — an invoice is "not paid" from the moment it
  is created.
- Status can become "paid" automatically when the client pays online, or by the
  User **manually marking it paid**.

### 4.8 Online Payments
- Each invoice can have an associated **payment link** for the invoice's exact
  total and currency.
- The client can pay the invoice online via that link.
- Each User must complete a **payment onboarding** step before they can
  send/collect on invoices; until onboarding is complete, sending and collecting
  are blocked.
- Payouts go directly to the **User's own bank account**; the product takes
  **no platform fee**.
- When an unpaid invoice is edited in a way that **changes the total**, the old
  payment link is invalidated and a new one is generated.
- When the User **manually marks an invoice paid**, its payment link is
  deactivated/expired.
- When a client pays online, the invoice's status automatically flips to
  **"paid"**.

### 4.9 Send to Client (Email)
- The User can **send an invoice to the client by email with one click**.
- The email is sent to the **client's email address**.
- The email contains a short message plus the **payment link**, with the
  **PDF attached**.
- The **sending User is BCC'd** so they keep a copy.
- Replies go to the **User's profile email** (reply-to).

### 4.10 Resend Flow
- The User can resend an invoice to the client.
- If an **already-sent** invoice is edited and saved, the app shows a
  **"Resend to client?" confirmation** before resending.
- The app **never auto-resends** without explicit confirmation.
- The app tracks when an invoice was last sent.

### 4.11 Dashboard
A summary home screen showing:
- **Summary stats**: total outstanding, total paid, and relevant counts.
- **Recent invoices**.
- **Quick actions** (e.g. create a new invoice).

## 5. Functional Rules

### 5.1 Invoice Numbering
- Invoice numbers are **per-user and sequential**.
- Format is **year-prefixed**: `INV-2026-0001`, `INV-2026-0002`, …
- Numbers are generated **automatically and reliably without gaps from
  collisions**; the User never enters or edits the number.

### 5.2 Single Currency per Invoice
- Currency is chosen from a **fixed shortlist** (EUR, USD, GBP, plus a few other
  common currencies).
- Exactly **one currency per invoice** — no mixed-currency line items.
- Amounts are shown to **2 decimal places**, with number/date formatting based
  on the locale appropriate to the selected currency.

### 5.3 Edit / Delete Restrictions (Lifecycle)
- An invoice is **"not paid"** from creation (no draft state).
- An invoice can be **edited or deleted only while it is "not paid"**.
- **Paid invoices are locked** — they cannot be edited or deleted.
- Deleting a not-paid invoice is a **hard delete**: the invoice, its stored PDF,
  and its payment link are all removed/deactivated.

### 5.4 Snapshots (Historical Accuracy)
- The **sender ("From")** and **client ("To")** details are **frozen onto each
  invoice at creation time**.
- Later edits to the profile or to a client **do not change historical
  invoices**.
- Deleting a client does not alter past invoices — they keep their snapshot of
  the client's details.

### 5.5 Line Item & Tax Calculation
- Unit type (**hours/flat**) is a **label only**; the math is always
  `Quantity × Price`.
- VAT is **tax-exclusive**: per-line VAT is added on top of the line amount.
- **Tax** = sum of all per-line VAT amounts.
- **Total** = Subtotal + Tax.
- No discounts, shipping, or adjustment lines.

### 5.6 Dates
- **Invoice Date** defaults to **today**.
- **Due Date** defaults to **today + 14 days**.

### 5.7 Data Ownership
- Every User only ever sees and manages **their own** data (profile, clients,
  invoices, PDFs).
- A User can never access another User's data.

## 6. Out of Scope / Non-Goals

The following are explicitly **not** part of this product:

- **Multi-user organizations, teams, or shared accounts.** Single role only.
- **Multiple roles / admin role.**
- **Branding customization** (logo upload, custom colors, custom invoice
  layouts/templates).
- **Bank account fields, interest fields, or a "type" field** on invoices.
- **Discounts, shipping, or adjustment line items.**
- **A "draft" invoice state.**
- **Mixed-currency invoices.**
- **Platform fees / marketplace commission** on payments.
- **Additional payment-confirmation emails** beyond the status update.

---

## 7. Non-Functional Requirements

- **Responsive UI** that works on common desktop and mobile screen sizes.
- **Basic form validation** with clear error messaging on all input forms.
- **Consistent, readable PDF** output across invoices.
- **Reliable online-payment status handling** (invoices reliably reflect paid
  status after payment).
- **Basic email error handling** (the User is informed when sending fails).
- **Authentication and per-user data protection** so each User only accesses
  their own data.

## 8. Pages / Screens

1. **Landing / Auth entry** — minimal; routes to Login / Register.
2. **Register** — create an account (email + password).
3. **Login** — sign in (email + password).
4. **Forgot password** — request a reset and set a new password.
5. **Dashboard** — summary stats, recent invoices, quick actions.
6. **Create invoice** — fixed-layout invoice form with line items and live
   totals.
7. **Previous invoices** — paginated list with row actions.
8. **Invoice details / preview** — full invoice view with actions (view PDF,
   edit, delete, resend, download, mark paid).
9. **Clients list** — list of clients with management actions.
10. **Add / edit client** — client form.
11. **Profile / sender details settings** — manage sender details and complete
    payment onboarding.

---

## 9. Glossary

- **User** — the single role; an authenticated freelancer using the app.
- **Sender / From** — the User's own details placed at the top of an invoice.
- **Client / To** — the recipient of an invoice.
- **Snapshot** — a frozen copy of sender/client details stored on an invoice at
  creation, ensuring historical invoices never change.
- **Outstanding** — invoices that are "not paid".
